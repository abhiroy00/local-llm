# Architecture

ChatViewProvider owns session history, modes, cancellation and workspace-scoped tools. React displays streamed Markdown/code, model/mode selectors, attachments, checklists and expandable tool output in a Secondary Side Bar webview. OllamaService makes local-only host requests and parses bounded NDJSON.

AgentService uses per-tool JSON-schema constrained tool/final decisions with Zod validation. Explicit read-only requests enforce Plan policy. Read-only architecture inspections constrain discovery to listed unread files, retain provenance, and require file reads/references before accepting an initial sampled summary. These checks do not validate semantic truth of model prose. Recent conversation context, root AGENTS.md guidance and explicitly attached source excerpts are bounded; recent results are bounded; the whole repository is never assembled into a prompt. Configurable step limits (40 by default), bounded JSON repair, duplicate detection and deadlines constrain work. Host-generated execution records distinguish actual edits/test exits from model prose.

WorkspaceService enforces paths, device-name restrictions, nested ignores, text limits and link exclusions. Search/listing run in-process with strict limits. Symbols, document outlines, definitions and references use VS Code language providers; every returned source path is filtered. Diagnostics come from VS Code language extensions. Tasks target one root.

ToolSchemas describes 25 tools, schemas and policies. ToolRegistry validates and dispatches calls. Plan blocks mutations/processes independently of model output. FileEditor previews virtual diffs, checks hashes/document versions/dirty state, applies WorkspaceEdit, saves and keeps 20 persistent revert records grouped by task. Patches are exact and single-file. Targeted text replacement requires one exact occurrence and the current full-file hash. Read excerpts support 1-based line ranges.

BackgroundService owns one approved npm dev/start process per registry, bounds output/lifetime, and reports exit state; disposal kills its process tree. FileEditor groups task records, previews aggregate diffs and preflights final file states before sequential approved undo. Named-file implementation tasks use a smaller catalog and schema-guided initial reads; bounded excerpts and hashes survive recent-result eviction.

Terminal restricts commands, previews npm scripts/hooks and terminates process trees on timeout/cancellation. Git output is filtered; external diff/textconv/fsmonitor are disabled.

Optional SemanticIndex uses local embeddings, stale hashes and cosine ranking. A validated, atomic local JSON store in VS Code extension storage retains up to 100 conversations per workspace, bounded semantic vectors per workspace/model and the last 20 workspace-scoped undo records. Drafts still use VS Code state. Data is unencrypted and remains on the local machine. SQLite, Tree-sitter grammars and ripgrep acceleration remain deferred scale improvements. No syntax-aware whole-repository database is claimed.

ModelCatalog maps curated local tags to official DeepSeek checkpoint/distribution metadata. Hardware reports total host RAM and estimated home-drive free space. The sidebar can explicitly pull catalog models through bounded/cancellable NDJSON, then refresh/select them; no cloud inference provider is configured. Selected models persist in VS Code global state. AnswerFilter handles legacy R1 think blocks; separate reasoning fields never become tool decisions. ProcessSpec isolates Windows npm launching from shell-free POSIX/toolchain paths and is unit tested with both platform settings.

Small explicit multi-file repairs use a staged adapter: complete source/test reads and applicable root/nested guidance, one model content proposal per bounded source, host-injected path/hash, normal FileEditor approval, tests after the edit batch, and at most one refresh/repair pass. Only successful test exits establish verification; file assessments and model behavior descriptions are not proof. The native harness records bounded decisions/results only for disposable fixtures. React DOM tests bridge actual component buttons to the host handler and file undo; they do not capture native layout.
