# Security

No telemetry or automatic model downloads. Chat sends messages to local Ollama; Plan/Agent can send allowed source excerpts and approved command output. Only localhost/127.0.0.1/::1 HTTP(S) origins are accepted without credentials, paths, query strings or redirects. Ollama's own routing/storage is managed separately.

Tools require a trusted local folder. Plan cannot mutate or spawn. Decisions/arguments are schema-validated. Unknown tools, traversal, Windows device names/alternate streams, secret filename patterns, ignored files and symbolic/hard links are rejected. Filename exclusions do not guarantee arbitrary source or command output is free of credentials.

Each file change opens a native diff and requires a matching sidebar approval card. Approval IDs and cancellation prevent stale decisions. Dirty/hash/version checks reject stale edits. Stop does not undo earlier edits. Revert requires approval and retains the last 20 workspace-scoped records across restarts. A save failure may leave an unsaved editor change. Approval is for a complete one-file proposal; partial-hunk selection is not implemented. Keep Git backups.

Commands are allowlisted, previewed and approved separately. Approved scripts/tests execute project code and can modify files or use networks: this is not an OS sandbox. npm scripts/hooks are previewed. Git commit/push/reset and destructive commands are unavailable. Git output is filtered to allowed files.

CSP uses a random nonce. Raw model HTML is not executed; links/images are inert. The live activity UI displays bounded excerpts of approved command output and applied diffs; activity is not persisted as a separate audit log. Conversation history (up to 100 sessions per workspace), semantic vectors and undo contents persist as unencrypted local JSON in VS Code extension storage; deleting a conversation does not remove undo records or vectors. Drafts persist in VS Code state. Do not store secrets in prompts or approved files.

Known limit: checks cannot guarantee race-free access against another malicious local process swapping directory entries. Concurrent edits, root switching and process termination need wider platform testing. This preview is not a hardened sandbox for adversarial repositories or a deployment tool.

DeepSeek setup downloads only explicit catalog profiles through the loopback Ollama pull API after a user setup action. It does not accept arbitrary remote model URLs, execute downloaded Python model code, call hosted Hugging Face/DeepSeek inference or collect API keys. Ollama manages model storage and downloads; partial cached layers may remain after cancellation. Source buttons open fixed official Hugging Face URLs. Model selection is retained in VS Code global state. DeepSeek R1 reasoning traces are excluded from displayed answers/tool decisions.

Task checkpoints cover FileEditor changes only. Whole older groups are evicted at the 20-record retention limit; task undo is sequential and may stop partway after rejection, cancellation or a concurrent edit. Background npm dev/start scripts run with the editor user’s privileges and can expose servers according to project code. They require script/hook approval, are limited to one per workspace and ten minutes, and are terminated with the registry. Their output is bounded; readiness is not inferred from process status.

Focused small-file proposals obtain paths and hashes from host-held successful reads, include complete applicable root/nested project guidance, and still require native diff approval. Malformed/out-of-scope proposal objects and raw binary/control characters are rejected before mutation. This does not make generated content semantically correct: actual tests are still required, and the small local model has known failing cases.
